# 可视化计算器 · 前端（学号 832401217）

前后端分离计算器系统的**前端部分**。界面、按钮交互、表达式输入与前端校验在这里；
**所有计算最终都由后端完成**，本仓库不含任何计算结果逻辑。

> 这是软件工程课程「前后端分离计算器系统」个人作业的前端仓库。
> **后端仓库**：[832401217_calculator_backend](https://github.com/qihangpeng580-ui/832401217_calculator_backend)
> **在线地址**：https://qihangpeng580-ui.github.io/832401217_calculator_frontend/

---

## 一、项目介绍

一个可在浏览器中直接运行的网页计算器前端，负责：

- 用户界面呈现（显示屏、键盘、历史记录区）
- 按钮点击与键盘输入的事件处理
- 表达式输入与**前端输入校验**（括号配对、连续运算符、小数点、非法字符等）
- **调用后端接口计算**，显示后端返回的结果
- 把后端返回的错误码翻译成中文提示
- **历史记录的展示、搜索、删除、清空**（数据全部来自后端数据库）

**设计上的一个硬约束**：前端**不**解析、**不**计算表达式。输入框里永远只是一串字符，
唯一的算术来源是后端接口。所以把后端停掉之后，界面依然可以正常输入与点击，
但**不可能"偷偷算出来"** —— 这是作业要求的自查方法。

> 实测验证：`tools/e2e-integration.mjs` 的最后一项就是"停掉后端再按 `=`"，
> 确认结果行不会出现答案，只提示无法连接。

## 二、技术栈

| 项目 | 选择 | 说明 |
|---|---|---|
| 语言 | 原生 HTML + CSS + JavaScript（ES Module） | 没有框架、没有编译 |
| 运行环境 | 任意现代浏览器（Chrome / Edge / Firefox） | 双击 `src/index.html` 即可 |
| 依赖 | **零第三方依赖** | 不需要 `npm install` |
| 打包 | 自写脚本合并为传统脚本 | 原因见第四节，是真实踩到的坑 |
| 测试 | Node.js 内置断言脚本 | 仅测试用；不跑测试则连 Node 都不需要 |

**为什么不用框架**：作业要求「结果必须由后端产生」，前端职责是交互与展示。
用原生实现能把事件驱动、模块划分这些知识点做得更清楚，也让助教一眼能读完代码。

## 四、运行方法

### 4.1 只看界面（不需要后端）

```powershell
# 在文件管理器里双击 src\index.html
# 或命令行：
start "" "src\index.html"
```

界面、按钮交互、输入校验都能用。但按 `=` 会提示"无法连接后端服务" ——
因为**计算必须由后端完成**，这正是设计要求。

### 4.2 完整功能（需要后端一起跑）

```powershell
# ① 先启动后端（另开一个终端）
cd "..\832401217_calculator_backend"
py -3.12 run.py

# ② 再打开前端
start "" "src\index.html"
```

后端启动后，显示屏右下角会变成「**后端已连接 · 结果由后端计算**」，
按 `=` 就能看到后端算出的结果，右侧历史区也会从数据库读出记录。

> **★ 为什么页面加载的是 `js/bundle.js` 而不是那些 ES 模块：**
> 浏览器在 `file://` 页面里**不执行 `<script type="module">`** ——
> 双击打开时模块会被拒绝加载，交互代码全都不会运行，页面看起来正常、点按钮却毫无反应。
> （真实踩过这个坑：用本地 HTTP 服务器做的自动化测试全部通过，用户双击打开却什么都点不动。）
> 所以构建时把模块合并成一个传统脚本 `bundle.js`，双击即可使用。
>
> 改了 `src/js/` 下的源码之后，需要重新生成 bundle：
> ```powershell
> node tools\build-bundle.mjs
> ```
> `bundle.js` 是生成物，不要手工编辑。

**键盘映射**

| 按键 | 作用 |
|---|---|
| `0`–`9`、`.` | 输入数字与小数点 |
| `+` `-` `*` `/` | 四则运算符（也接受 `×` `÷`） |
| `(` `)` | 括号（也接受全角 `（` `）`） |
| `Enter` 或 `=` | 提交给后端计算 |
| `Backspace` | 退格 |
| `Esc` 或 `Delete` | 清空 |
| `n` | 正负号切换（对应界面上的 `±`） |

## 五、配置说明（与后端的连接方式）

### 5.1 后端地址在哪配

**`src/js/config.js` 一个文件，一行：**

```js
export const API_BASE_URL = 'http://127.0.0.1:8000';
```

| 场景 | 该填什么 |
|---|---|
| 本地开发（前后端都在本机） | `http://127.0.0.1:8000` |
| 后端部署在别的地址 | 改成那个公网地址，例如 `https://calc-api.example.com` |
| 前后端同源部署 | 留空字符串 `''`，请求会打到 `/api/...`，不存在跨域问题 |

> ⚠️ 改完 `config.js` **必须重新打包**（`node tools/build-bundle.mjs`），
> 因为页面加载的 `bundle.js` 里内联了这份配置。
> 这一点踩过：只改了源文件却忘了打包，页面一直在连旧地址。

### 5.2 接口一览

| 方法 | 路径 | 前端用在哪 |
|---|---|---|
| `POST` | `/api/calculate` | 按 `=` 时提交表达式 |
| `GET` | `/api/history` | 打开页面时拉列表；搜索时带 `keyword` |
| `DELETE` | `/api/history/{id}` | 每条记录右侧的「删除」按钮 |
| `DELETE` | `/api/history` | 右上角「清空」按钮 |
| `GET` | `/api/health` | 打开页面时检查后端是否在线 |

请求与响应的完整格式、错误码表，见**后端仓库的 README**。

### 5.3 前端如何展示后端错误

`ui.js` 里有一张错误码到中文的映射表（`SERVER_ERROR_TEXT`）：

| 错误码 | 前端显示 |
|---|---|
| `INVALID_EXPRESSION` | 表达式不合法，请检查括号与运算符 |
| `DIVISION_BY_ZERO` | 除数不能为 0 |
| `EXPRESSION_TOO_LONG` | 表达式过长，请拆开计算 |
| `RECORD_NOT_FOUND` | 这条历史记录不存在或已被删除 |
| `BAD_REQUEST` | 请求格式不正确 |
| `INTERNAL_ERROR` | 服务器内部错误，请稍后再试 |

**判断对错的权力始终在后端**，前端只负责把错误码翻译成人话并标红。

### 5.4 数据库初始化

前端不涉及数据库。建库方式见后端仓库 README 的「数据库初始化」一节
（后端服务启动时会自动建表）。

## 六、测试

### 1. 输入规则自测（快，几毫秒）

```powershell
node src\test\test-input-model.js
```

49 条断言：基本输入、开头运算符限制、连续运算符、小数点规则、括号配对、
正负号、退格与清空、长度上限、提交前校验、非法字符白名单。

### 2. 端到端点击测试（约 20 秒，**不需要后端**）

```powershell
node tools\e2e-click.mjs
```

37 项断言，用**真实鼠标点击**逐个点按钮。重点覆盖：

- 加减乘除、小数、括号、一元负号依次点击后的表达式
- **表里分离**：内部必须是 ASCII 的 `*` `/`，界面显示 `×` `÷`
- 空表达式下按 `+ * / )` 应被拒绝并给出错误提示
- 按 `=` 后**结果仍是占位**，前端不得产生任何计算结果（作业硬性要求）
- 21 个按键逐个点一遍，确认没有"点了没反应"的键

### 3. 前后端联调测试（约 30 秒，**需要后端**）

```powershell
node tools\e2e-integration.mjs
```

这个脚本会**自己起一个真实后端**（临时数据库）、自己托管页面、
用真实浏览器真的点按钮，共 **30 项断言**，覆盖：

- 后端在线时界面显示「后端已连接」
- 点 `12+8=` → 结果行显示 **20**（来自后端）
- 复合表达式：优先级、括号、一元正负号、小数
- 除零 → 显示「除数不能为 0」并标红；**失败的计算不写入历史**
- 历史列表渲染、条数统计、搜索、删除单条、清空
- **重新打开页面后历史依然存在**（证明真的持久化在数据库里）
- **停掉后端再按 `=` → 得不到结果**（证明前端没有偷偷算）

**为什么必须有这一层**：前两层分别验证"输入规则"和"界面交互"，
但都没有证明"前端真的把表达式发给了后端、后端真的算出了结果、结果真的回到了界面上"。
而这个项目已经吃过两次"假绿"的亏（详见 `docs/设计说明.md`）：
测试全绿但真实使用方式下功能是坏的。所以联调测试必须是真实 HTTP + 真实浏览器 + 真实点击。

### 4. 已部署页面验证（约 15 秒）

```powershell
node tools\verify-deployed.mjs
```

对**已部署的公网地址**做同样的真实点击验证，确认线上那份也能用。

## 七、部署

前端是纯静态页面，可以直接托管在 GitHub Pages（免费、永久在线）。

```powershell
# 发布到 gh-pages 分支
py -3.12 tools\deploy_pages.py

# 首次发布后，清理 gh-pages 上从 main 派生时带过来的源码文件
py -3.12 tools\clean_pages_branch.py

# 验证线上页面真的能用（真实浏览器点击）
node tools\verify-deployed.mjs
```

发布脚本会把 `src/` 里的**内容**（而不是 `src` 目录本身）放到站点根目录，
这样 `index.html` 里的相对路径（`css/style.css`、`js/bundle.js`、`assets/nailong.png`）
完全不用改。

**在线地址**：https://qihangpeng580-ui.github.io/832401217_calculator_frontend/

> 注意：线上页面要连后端的话，需要把 `src/js/config.js` 里的 `API_BASE_URL`
> 改成后端的公网地址，重新打包后再发布一次。
