# 可视化计算器 · 前端（学号 832401217）

前后端分离计算器系统的**前端部分**。本轮完成界面、按钮交互、表达式输入与前端校验；
**所有计算最终都由后端完成**，本仓库不含任何计算结果逻辑。

> 这是软件工程课程「前后端分离计算器系统」个人作业的前端仓库。
> 后端仓库将在前后端联调阶段单独建立。

---

## 一、项目介绍

一个可在浏览器中直接运行的网页计算器前端，负责：

- 用户界面呈现（显示屏、键盘、历史记录区）
- 按钮点击与键盘输入的事件处理
- 表达式输入与**前端输入校验**（括号配对、连续运算符、小数点、非法字符等）
- 显示后端返回的结果，以及把后端返回的错误码翻译成中文提示
- 发送计算请求与历史记录增删请求（接口已预留，见第五节）

**设计上的一个硬约束**：前端**不**解析、**不**计算表达式。输入框里永远只是一串字符，
唯一的算术来源是后端接口。这样停机验证时（停掉后端）前端不可能"偷偷算出来"。

## 二、技术栈

| 项目 | 选择 | 说明 |
|---|---|---|
| 语言 | 原生 HTML + CSS + JavaScript（ES Module） | 没有框架、没有编译 |
| 运行环境 | 任意现代浏览器（Chrome / Edge / Firefox） | 双击 `src/index.html` 即可 |
| 依赖 | **零第三方依赖** | 不需要 npm install，不需要构建 |
| 测试 | Node.js 内置断言脚本 | 仅测试用；不跑测试则连 Node 都不需要 |

**为什么不用框架**：作业要求「结果必须由后端产生」，前端职责是交互与展示。
用原生实现能把事件驱动、模块划分这些知识点做得更清楚，也让助教一眼能读完代码。
代价是没有脚手架带来的便利；作为补偿，四个源文件各自有明确职责边界。

## 四、运行方法

```powershell
# 方式一：直接双击打开（推荐，什么都不用装）
#   在文件管理器里双击 src\index.html

# 方式二：用命令行打开（Windows）
start "" "src\index.html"
```

无需安装、无需启动服务、无需联网。打开后即可用鼠标点击按钮或直接用键盘输入。

> **★ 为什么页面加载的是 `js/bundle.js` 而不是那四个 ES 模块：**
> 浏览器在 `file://` 页面里**不执行 `<script type="module">`** ——
> 双击打开时模块会被拒绝加载，交互代码全都不会运行，页面看起来正常、点按钮却毫无反应。
> （真实踩过这个坑：用本地 HTTP 服务器做的自动化测试全部通过，用户双击打开却什么都点不动。）
> 所以构建时把四个模块合并成一个传统脚本 `bundle.js`，双击即可使用。
>
> 改了 `src/js/` 下的源码之后，需要重新生成 bundle：
> ```powershell
> node tools\build-bundle.mjs
> ```
> `bundle.js` 是生成物，不要手工编辑。

**键盘映射**

| 按键 | 作用 |
|---|---|
| `0`–`9`、`.` | 输入数字与小数点 |
| `+` `-` `*` `/` | 四则运算符（也接受 `×` `÷`） |
| `(` `)` | 括号（也接受全角 `（` `）`） |
| `Enter` 或 `=` | 计算（本轮为提示，联调后调用后端） |
| `Backspace` | 退格 |
| `Esc` 或 `Delete` | 清空 |
| `n` | 正负号切换 |

## 五、配置说明（与后端的连接方式）

本轮**尚未接入后端**，因此页面右下角如实显示「后端未启用 · 结果由后端计算」，
按 `=` 只会给出提示，不会产生任何结果。

前后端联调阶段需要改的地方只有两处，且都不涉及结构改动：

1. **新增 `src/js/api.js`**，集中封装后端接口，例如：
   - `POST /api/calculate`，请求 `{ "expression": "(1+2)*3" }`
   - `GET  /api/history`
   - `DELETE /api/history/{id}`
2. **`calc-buttons.js` 的 `evaluate()`**：把当前的提示语句换成调用 `api.calculate()`，
   再把后端返回的 `result` 交给 `ui.render()` 显示；错误码交给 `ui.showServerError()`。

`ui.js` 里已经预留了后端错误码到中文提示的映射表（`SERVER_ERROR_TEXT`），
`DIVISION_BY_ZERO`、`INVALID_EXPRESSION` 等错误码可以直接使用。

**数据库初始化**：前端不涉及数据库，此项在后端仓库的 README 中说明。

## 六、测试

### 1. 输入规则自测（快，几毫秒）

```powershell
node src\test\test-input-model.js
```

覆盖 49 条断言：基本输入、开头运算符限制、连续运算符、小数点规则、括号配对、
正负号、退格与清空、长度上限、提交前校验、非法字符白名单。全部通过时输出：

```
全部通过：49/49
```

### 2. 端到端点击测试（慢，约 20 秒）

```powershell
node tools\e2e-click.mjs
```

用**真实的鼠标点击**逐个点按钮，核对表达式行与内部缓冲区。共 35 项断言，包括：

- 加减乘除、小数、括号、一元负号依次点击后的表达式
- **表里分离**：内部必须是 ASCII 的 `*` `/`，界面显示 `×` `÷`
- 空表达式下按 `+ * / )` 应被拒绝并给出错误提示
- 按 `=` 后**结果仍是占位**，不得产生任何计算结果（作业硬性要求）
- 21 个按键逐个点一遍，确认没有"点了没反应"的键
- 页面无脚本错误

**为什么必须有这一层**：截图工具是直接调用模块接口设置状态，
绕过了"点击 → 事件委托 → 按键处理"这条真实链路。
界面截图可以完全正常、而用户点按钮毫无反应（真实踩过：键盘错位导致点到缝隙里）。
只有真实点击才能覆盖这条路径。
